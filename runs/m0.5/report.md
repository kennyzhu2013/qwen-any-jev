# M0.5 · 真实人工复核数据上的 off-ramp 对比

- 模型：`Qwen/Qwen3.5-4B`；评测集：`eval/goldens.jsonl`（1447 条，2026-07-29 单日）
- 拆分：cal 580 / dev 289 / gate 578
- gate 标签：正常 64 / 涉诈 514
- 协议：所有选择（probe 层/L2/类权重、prior 强度、温度）只在 cal/dev 上做；gate 只评分一次。
- 任务定义与 rubric：`eval/task.py`；标签语义与限制：`eval/README.md`。

## 1. 结论

- 最佳非 probe baseline：**raw+固定prior**，balanced accuracy **0.577**，涉诈 recall **0.889**，正常 recall **0.266**。
- 线性 probe（dev 上按 balanced accuracy 选）：balanced accuracy **0.742**，涉诈 recall **0.875**，正常 recall **0.609**，ECE **0.065**。
- 线性 probe（风险优先：dev 涉诈 recall≥0.95 下最大化正常 recall）：balanced accuracy **0.569**，涉诈 recall **0.967**，正常 recall **0.172**。
- probe 相对最佳 baseline 的 balanced accuracy 差：**+0.165** (95% CI [0.086, 0.241])。
- 预注册门禁：**未通过**。（bal≥0.70, 涉诈 recall≥0.95, 正常 recall≥0.50, ECE≤0.10, 相对 baseline bal 提升≥5pp 且 CI 下界>0）
  - ✅ balanced accuracy ≥ 0.70：0.742
  - ❌ 涉诈 recall ≥ 0.95：0.875
  - ✅ 正常 recall ≥ 0.50：0.609
  - ✅ ECE ≤ 0.10：0.065
  - ✅ 相对 baseline bal ≥ +5pp：+0.165
  - ✅ paired bootstrap CI 下界 > 0：[0.086, 0.241]
- baseline 按协议在 dev 上冻结为 raw+固定prior；gate 上 L0+固定 prior 的 bal 反而更高（0.603 vs 0.577）。不改选 baseline；若以 L0+固定 prior 为参照，probe 的 Δbal 仍为 +0.139 （95% CI [0.056, 0.222]）。
- 关键限定：冻结 probe 的唯一失败项是**涉诈 recall**（0.875），不是平衡性；gate 上事后把阈值扫到涉诈 recall 0.951 时正常 recall 恰为 0.500，但 dev 在同一约束下只有 0.219 —— 这是 32/64 条正常样本下的边界波动，不是一个稳健的可用操作点。

**判定：线性头未过门禁，暂不进入 LoRA 训练。** 按预注册协议，LoRA 是下一层评估对象；但 dev/gate 的错误结构显示瓶颈更像是「标签依赖通话外业务上下文」与操作点，而不是模型容量。前置动作是补齐风险等级/违规类型与业务归属标签、重定义漏判代价，再用同一套 gate 复评；直接开训只会把同样的标签噪声蒸馏进学生模型。

- gate 上若复核容量 40%，`hi≈0.713` 可自动拦截 69.6% 涉诈，但 17.2% 正常被误自动拒绝；容量 50% 时自动拦截 65.0%、正常误拒 14.1%（同一阈值 dev 仅 6.2%，正常类 32 条不足以定阈值）。

- 采用前需要业务给出**误拒一个正常客户 vs 人工复核一条**的成本比，并把正常类样本扩到 300–500 条后重定阈值；现有 dev 的 32 条正常无法支撑阈值外推。
- 代价陷阱：gate 涉诈占比 88.9%，「全部自动拒绝」的正常误拒成本只有 0.111×C_FP/行；只要单条复核成本高于 0.111×C_FP，无约束的代价最小化就会退化为全部拒绝。操作点必须先设硬约束（如正常误拒≤10%），不能直接做代价最优。

## 6. 判读与下一步

- 本评估集只有一天，gate 不是时间外推；正常类 gate 只有 64 条，正常 recall 的 95% CI 约 ±12pp，不能支撑细粒度上线承诺。
- 类别极不平衡（gate 涉诈 514/578 = 88.9%）：raw 的 gate accuracy 0.879 低于「全判涉诈」常数基线 0.889；accuracy 在本任务上没有判别力，必须看 balanced accuracy 与两类 recall。
- 源标签 `涉诈` 包含低风险违规（备注中 10 条明确写“低风险”），不是严格的刑事诈骗标签；风险等级未系统标注，未做门禁。
- dev 上正常类与涉诈类的贷款词（贷款/额度/信贷/资金/利息等）覆盖率分别为 65.6%（21/32）与 66.5%（171/257），单看通话文本几乎不可分；大量正常样本是合规贷款营销，而部分涉诈样本是违规催收/荐股。这说明标签很可能取决于通话外的业务归属/资质，而不是话术本身——这是任何 transcript-only 模型（probe 或 LoRA）的共同上限。
- 三路分流（§3.2）：当前概率只能支撑「高置信涉诈自动拦截 + 其余转人工」，不能自动放行正常；复核容量 40% 时自动拦截 69.6% 涉诈，但 17.2% 正常被误自动拒绝。采用前必须先定成本比与正常误拒上限。
- 如果 probe 未过门禁，下一步不是直接训 LoRA，而是：（a）补齐风险等级/违规类型标签；（b）按类型分层检查教师质量；（c）确定漏判/误判代价与操作点；再进入 M1。
